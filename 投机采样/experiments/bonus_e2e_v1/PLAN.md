## 计时范围

固定状态测试使用原始 init3/init4 的 chunk14 真实快照，历史 KV 2016、池容量 2160；输入、完整 30 层有效 KV、scheduler 与 RNG 均恢复。固定状态只启动一个部署模型，不新增 EGL/episode。每个状态先执行一次原 Torch bonus 精度 oracle，再对三种配置各预热一次，随后执行三种配置的六个平衡排列，共 22 次完整 chunk；两状态合计 44 次。

固定状态主计时为完整 `infer` 墙钟：开始前同步 CUDA，返回后同步 CUDA，再停止计时。包含视频/动作生成、draft、验证、分支选择、fallback、bonus、主机调度及原始输出 CPU 拷贝。保留原 request 计时作为次指标，恢复快照、预热和结果哈希在计时外；冷模板准备、模型加载和快照恢复仍计入 GPU 总预算。主指标不能只计 verifier kernel、减少的前向次数或被接受的更新数。

三方完整任务均重新计时：T=原始 target-only，OFF=direction + shared KV + O1/O2/O3，BONUS=OFF 加已有 bonus。三轮各两个独立 EGL worker，init3/init4 与三种配置平衡配对；任务为 LIBERO Long task0，原完整 horizon=800，无人为 chunk 截断。episode 计时保留 reset、推理、动作提交和环境执行。历史 T/O3 仅用于数值轨迹回归，不作为本轮主计时分母。两个状态和一个任务只能形成 pilot；双 worker 收集的完整任务耗时应标明并发条件，不当作单部署延迟。

同状态 GPU oracle 必须输出、分支计数、返回值、RNG/scheduler 和全部 30 层有效 KV/元数据逐位一致。独立 CPU 重新审核归档输出与轻量最终状态；完整 KV 的逐位比较在 GPU worker 内进行，未归档全 episode KV。BONUS 相对 OFF 会改变真实后续动作和观察，不能要求两者轨迹逐位一致；成功率、轨迹步数与完整耗时需要分开报告。
