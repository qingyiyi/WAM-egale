# 短 KV：原 Torch、共享 S0、行证明复用 S1 三组对照

CPU 原型已通过21项接口、失效保护和机制检查，另有独立字节/源码审计。这里仅在新的私有包装验证 GPU 数值与完整 verifier 性能；原测量、公共实现和受保护 HW 状态均冻结。

## 测量与接受条件

- 真实短档 T-init3-chunk1/frame4，原快照144历史；视频缓存更新后272历史加16当前 token，KV288。原 Torch 重捕获必须恰好50次非terminal前向和27个自然 verifier 查询，停止在 action terminal 的模型计算之前。
- R为原 Torch；S0为现有共享数学路径且行证明复用关闭；S1为同一共享数学路径且复用开启。开关在原计时函数外选定；三者直接继承原 Runtime.sequence，staging、lease、首次建立、keys、写前 journal fsync、release 均保留在计时内。历史恢复和CPU输出检查在计时外。
- 各组先完整预热27个查询，S1首次预热记录并核对全部30层 Q/K/V 和 attention，对应同次 capture 的原 Torch 首查询。记录仅在预热保留，正式测量前清理。无需额外attention微调用。
- 正式六轮按三组的全部六个排列执行：R/S0/S1、R/S1/S0、S0/R/S1、S0/S1/R、S1/R/S0、S1/S0/R。各组在每个位置出现两次；每一组对的先后次序各三次。每轮每组覆盖完整30层和全部27个变化输入。18份实际CPU输出完整保存，全部486个与同次原 Torch gold 逐位相等才接受；没有删样或重跑。
- 独立比较R→S0、R→S1、S0→S1，复用原六对统计规则：MAD/median≤7%；中位数下降至少5%且六对均快才为positive_pilot。负向及混合结果照实保留。CPU的30→1检查次数不当作GPU加速证据。
- 如任一对没有稳定positive信号，仅在正式测量全部完成后追加首查询R/S0/S1各一次profiler诊断，最多192MiB。该诊断用于解释原因，不能替代OFF数据。新增CPU失效保护已通过；本轮不声称重新执行过新增GPU故障注入，也不作生产接入验收。
