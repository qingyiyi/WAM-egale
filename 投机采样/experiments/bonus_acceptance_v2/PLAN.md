# Bonus 开启、接受率与任务轨迹：先质量、后速度

用户优先级：把 bonus 开启；先确定接受率、降噪推进和环境轨迹长度的关系，改进接受率，然后确认加速比。原始 T baseline、旧 OFF 和已封存 BONUS 证据不变。

- [x] 建立研究默认 preset：bonus ON、A_off、共享 KV、O1/O2/O3、原阈值 0.007839680526450805。
- [x] 检查选路：优先最大可接受深度，再按原总误差与节点顺序；4,096 组穷举证明同树深度不降低，深度相同保留原选路。
- [x] CPU 完整 50 步 BF16：两个策略、首块/后续块、三档阈值，12 对输出、KV、调度器、RNG、接受记录一致。
- [x] 原始 Torch 与共享 O3 的实际 GPU 数值检查：两份现有长 KV 真状态，每份两个策略各原始/优化两次，共八个完整 chunk。
- [x] 两个并行 EGL worker、两轮交叉分配，GLOBAL 与 DEPTH 都开启 bonus；init3/4 四个完整任务，保留实际失败与全 800 步 horizon。
- [x] 按 sigma、首块/后续块、chunk 连接接受深度与实际环境步数；验证 GLOBAL 重现旧 BONUS 动作/环境/RNG。
- [x] 决定是否提升 DEPTH 为研究默认，追加 HW、检查旧封存证据和受保护状态。

唯一策略变量是 select：先最大接受深度，再总误差。阈值、目标/小模型、七个节点、CFG、50 步降噪及动作提交/环境逻辑相同。诊断只使用已回读的 CPU 六个误差；不增加 target forward。

每轮接受深度 0/1/2 时，bonus ON 的实际降噪推进为 1/2/3；平均推进量为 `1 + P(首层接受) + P(两层接受)`。环境步数由策略动作及成功条件决定，没有单调关系。

提升 DEPTH 的门槛：完整接受率与平均推进量都改善、匹配成功率不降、环境总步数不超过当前 GLOBAL 和原 T、最长任务不超过原 T 的 300 步。两个状态仍属于开发试验，不作为多任务泛化结论。

新独立资源计划：最多 16,640 次 target forward、5 个模型启动、4 次 EGL 初始化、35 分钟 GPU 总阶段（v1 诊断上下文错误的 61.885 秒及保守预留 640 次另计，完整保留）；累计硬上限仍为用户批准的 5 小时。累计前向预留上限调整到 60,000（此前 50,000 是代理自定，旧文件不改）。每任务前向预算 4,000，覆盖失败全 horizon；无 GPU 重试。输出至多 2 GiB，磁盘至少保留 12 GiB；GPU 空闲及外来进程检查、仅清理自己启动的进程。

本轮保留每块质量诊断，**不将耗时或调用数下降宣称为新加速比**。质量确定后，再按单部署模型的完整 policy 延迟及完整任务指标测速度，同时保留旧版本和原始 baseline 对照。
