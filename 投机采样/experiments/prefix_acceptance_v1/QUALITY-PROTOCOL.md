# 选路细化的质量协议

范围：原始 LingBot-VA target-only（T）、当前 bonus/shared/O3 + depth_then_cost（DEPTH）、新 prefix_then_cost（PREFIX）。目标、A_off 权重、阈值 0.007839680526450805、50 步 action diffusion、20 步 video diffusion、动作提交及任务 horizon 800 均固定。新策略同一树的可接受深度不变，只在最大深度为 1 时按保留首边误差选择父节点，拒绝子节点不参与排序。

## 本轮有限检验

- 真实长 KV GPU oracle：存档 init3/4 的两个相同完整状态；DEPTH、PREFIX 各原始 Torch / 共享 O3，共八个完整 chunk。DEPTH 必须复现上一轮原始 Torch 数值存档。
- 闭环：libero_10/task0/init6、7，每臂两个完整 episode，共六个；固定 seed20260922，两个独立 NVIDIA EGL worker 每轮并行，三轮交叉分配。init6/7 未用于近期续训的已知 init0/1 或旧评估 init2–5；更早 parent checkpoint 的历史暴露不能完全排除，且未用于上一轮 selector 选择；只能称未参与本轮选择的初态，不据此宣称任务泛化。
- 三轮分别为 T6/PREFIX7、DEPTH6/T7、PREFIX6/DEPTH7。无截断、无重试；失败/超时保留并计数，不补成功样本。
- 完整任务记录成功、环境步数、任务 horizon、实际 action chunks 和失败；去噪记录深度与 bonus，环境步与去噪步分别报告。
- 模型前向诊断和仿真记录存在，本轮耗时与 target 调用数不作为新加速比。

## 正确性与候选采用

CPU 逐树穷举要求最大合法深度与 DEPTH 相同，保留前缀成本不增加，阈值相等接受；无合法边与合法两层路径保持原选路。拒绝叶状态/方向不能影响一层接受后的 target 回退。完整生产 BF16 对照须覆盖两 selector、首/后续块、零/全接受/现用阈值的 12 对；GPU 必须核查输出、全部30层KV及元数据、scheduler、RNG、记录与资源清理。

开发采用门槛：六条任务完整记录；PREFIX、DEPTH、T 都 2/2 成功；PREFIX 总环境步数不超过 DEPTH，且最长任务不超过原 T 最长任务。若输出/命令/状态完全一致，可采用更直接的合法前缀语义，但必须明确没有观察到接受率、轨迹或速度提升。若候选失败或不满足质量门槛，保留当前 DEPTH。

这是有限研发筛选，不是总体成功率非劣证明。接受深度同树不下降不能保证后续轨迹质量，旧树成本反事实也不能代替完整任务。

## 后续训练与正式质量验证

训练标签必须在同一个 draft 查询状态、sigma、CFG与缓存条件下取 target；训练、阈值校准、最终测试按完整 episode/初态分组。声称跨任务泛化时留出整个任务。init3/4 以及本轮 init6/7 已进入开发比较，不再用于最终独立检验。

先固定当前阈值作 MLP 训练消融参照，再做相同数据/信息/预算的单层 Transformer 对照。阈值扫描仅用 calibration 集；模型/阈值定稿后才能使用最终测试集。正式非劣容忍度和样本量须在实验前另行固定，上一报告的 2百分点、1.05/1.10 只是讨论示例，本轮没有将其采纳为正式门槛。

成功率先于轨迹。双方成功的配对任务比较环境步数比的中位数、P90及置信区间；另报失败/超时，可按 horizon 计入全样本步数，不能把提前失败视为缩短轨迹。
