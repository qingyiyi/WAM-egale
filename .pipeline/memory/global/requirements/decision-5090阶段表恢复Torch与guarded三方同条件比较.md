# 5090完整阶段表加入guarded对照

后续完整阶段表同时列原Torch、已有guarded路径及自有persistent block。保留每阶段计算内容、tile数量与工作量、CTA内warp分工、同步边界、精度状态和相对原Torch的耗时比；完整层净收益单列。融合项不能重复计时，无法对应或未测项明确标注。

guarded指项目现有共享历史Attention路径与其余Torch算子的组合，不称为Torch官方实现，也不把其缓存收益另记成新的MegaTransformer贡献。三方使用相同真实输入、硬件/软件、缓存、dtype与计时边界；后续默认三方均eager、不使用CUDA Graph，旧Graph结果按原口径保留。

在5090上重新核对guarded数值与状态并实际测量后，才能填写其速度；未测时标UNKNOWN/未测，不借用A100数字。分阶段插桩与无插桩整层分开，报告插桩影响；当前来源不同的独立阶段耗时不直接相加或相乘成整层收益。

本决定替代日常汇报仅列Torch的限制，保留原记录。原预算、质量权限及生产准入不因此改变。

## 融合阶段和瓶颈展示（用户2026-10-23补充）

每次完整阶段表必须展示短/中/长KV逐阶段相对原Torch加速比，不能只给结构表让用户判断瓶颈；当前值未测时必须明确并安排已授权范围内补测，不挪用旧版本数字。原始绝对耗时保存在证据中，阶段占比和额外耗时用于解释瓶颈。

阶段行按当前实际融合和可独立计时边界组织，不能继续沿用27个旧数学步骤。LN与调制、RMS与RoPE、FFN1与GELU、FFN2与残差分别合并；当FFN1与FFN2存在执行重叠时，主表合并整个FFN子图，内部诊断另列，不虚构独立可加的阶段时间。层外预计算及缓存命中跳过工作单列，不计为warm block执行阶段。同步与布局等开销可以单列，不能隐藏。

此补充来自用户连续反馈“没有每阶段加速比无法判断瓶颈”和“融合了的阶段表也融合到一起”。延续三方同条件eager与当前预算，不改变数值门或扩大研究范围。
