# 5090条件选为性能基准，研发代码回同步本机

用户已取得RTX5090主机并授权登录核查。其偏好是环境和资源条件满足后，以该卡作为后续统一性能基准；这是有条件的平台选择，不代表源码已经适配、计时已经通过或旧A100结果可以换标成5090结果。

远端产生的全部项目研发源码，以及对应构建说明、必要结果和证据，阶段结束与释放机器前回同步本机`/rjs/cxz/论文探索`，不得仅留在临时租用机。源码小文件优先及时回传；大产物受本机剩余空间限制，提前核验容量与必要性。密码等凭据不写入HW、源码或GitHub。

初次授权仅环境检查；用户随后明确批准在新5090机器适配软件环境，并尝试重启排查空载利用率。优先在项目目录安装独立工具链和Python环境；重启限定该租用实例，不扩大到共用宿主机或BAAI服务器。计数器解除命令向用户说明作用域；当前未授权更换/卸载宿主驱动或更改平台权限，不运行smoke或研究SHA。不由本条自动启动新GPU研究、重置旧预算或搬迁正在运行的BAAI机器人队列。具体版本、占用与适配缺口保存在[环境结果](../../../maintenance/rtx5090-environment-20261023/RESULT.md)，不提升为长期硬件事实。

后续性能比较在同卡、同软件与相同计时边界下重建原Torch/自有实现对照；显存、shared、tile与指令差异仍按原可迁移性反馈处理。

用户对利用率异常的条件偏好（guideline，限新5090）：若确认不影响实际计算/计时，可保留异常说明而不继续修复读数。软件安装和功能开发不必因此暂停；正式性能仍需核对实际争用、频率与重复测量稳定性，不能仅凭空进程列表或问句将该异常定性为显示bug。计数器权限缺失不自动阻塞不依赖硬件counter的工作。

用户随后明确要求把现有算子迁移到5090，测性能、相对原Torch加速比和阶段表。本条已授权该有界移植测量，不再只是环境安装；沿既有真实输入与原数值边界，双方同卡同条件，当前两槽候选/原A100证据分别保留。GPU/墙钟上限及终态记录在本轮JOB，不继承过期窗口，也不据此重启其他研究队列。
