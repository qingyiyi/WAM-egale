# 算子交付明确源码入口与验证范围

当前算子研究的交付要提供可定位的主实现、替换入口和验证入口，结合真实源码说明计算顺序、Torch或自有CUDA各自承担什么。明确实际替换范围和已经验证的范围，不能把单attention验证、完整block验证和30层模型验证混称。

源码入口提供可复制的完整绝对路径，不能只显示链接短标签。实现覆盖与测量覆盖分别说明：测过完整block/30层不代表整个Transformer已实现为自有CUDA；默认attention替换与可选FFN1融合也必须分列。

协作交接还应提供真实block结构、参数与输入输出shape/dtype、已知stride范围、GEMM维度、共享/私有KV及DAG归约依赖，区分目标WAM block与TF draft。原fixture未公开、生产CUDA布局未保存等限制明确标注，不能让外部协作者误以为仅凭合成输入已重验全部真实场景。

本次源码交接包含可直接复制给另一agent的带读prompt，引用当前主实现、冻结baseline和实测报告；明确已实现与待实现部分，避免把固定warp角色、单kernel结构误讲成已完成的异步流水或已通过精度/性能验收。

## 源码带读方式

当前单层persistent算子的带读使用中文，每次只讲一个小节，先把用户追问解释清楚再继续。按数学结构与输入输出、Python到CUDA调用链、设备执行顺序与依赖、persistent与warp职责、GEMM tile、attention tile、norm/RoPE/调制/残差、baseline与profile的顺序推进。首次回复先给简短调用图、输入输出形状与阅读顺序，再开始第一节。

每节引用实际文件和准确行号，只贴必要的小段源码，用具体tile说明变量、输入输出、数据流、执行线程/warp、同步原因及当前限制。严格区分实现事实、设计目标、优化建议，以及完整block计时、插桩阶段计时、单GEMM kernel时间、理论资源上限和未知硬件计数。B14按独立候选的Q16解释，不讲成跨候选Q112 attention；动作latent维度与3072维隐藏状态分列。

此方式适用于本Cycle的源码学习与讲解。用户本次明确要求只读源码与已有报告，不修改或优化代码，不启动GPU、构建、实验或清理进程；该教学请求不触发M39或恢复任何旧作业，也不扩大后续实验授权。

后续工作按依赖列出已有成果、剩余缺口及下一优先项。当前继续遵循“先直接复制Torch完成复现，再研究优化”的已确认决定；具体子图/调度路线属于待证据支持的计划，不因列入工作清单就成为已获准启动的实验。

本要求适用于当前研究阶段的代码讲解与进展交付，不扩展资源、模型训练或正式性能权限。临时测量数字保存在Experiment，不存入此长期需求。
