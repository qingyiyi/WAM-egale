# FastWAM十步投机按剩余步数收缩树深并保留bonus

FastWAM动作采样仍完成同一官方scheduler的十次合法更新，不能把大模型调用次数与scheduler更新次数混淆。首次缺上一方向时由target完成bootstrap；剩余一次更新直接target；剩余两次更新时只展开一层draft，验证通过后提交该draft更新与下一时刻target bonus，正好结束。拒绝时只提交根节点target更新，再以target完成最后一次。当前双分支对应B3验证；后续适配需显式检查该新batch形状，不能沿用仅允许B1/B7的断言。

剩余三次及以上可沿既有两层树；需核对候选各自对应的时间与delta、拒绝/fallback/bonus以及前缀提交，不越界或重复更新。固定两层基线的完全接受路径审计应得到一次B1 bootstrap加三次B7验证，推进1+3+3+3=10；这四次target调用共处理22个状态，不代表四次B1成本，也不预设实际接受率。动态深度候选另按其实际配置核算调用与状态行数，不强制保持四次target调用。

## 动态深度的候选评估范围

用户追加要求将“前期步长小，可投机四至五步，后期回到两步”的思路纳入交接。已确认的是评估这一方向，具体深度表、候选拓扑和采用方案尚未确定。区分draft深度K与含bonus的最大推进K+1；每次K不超过剩余更新数减一，官方十步scheduler和误差门不因加深而改变。

交接需同时评估深度与宽度及实际成本，不能将早期两层高接受外推为四至五层必然接受。当前双分支完整树在K=4/5时分别有31/63个target验证状态；窄树、候选链或剪枝均作为独立候选，明确路径选择、逐边验证、最长合法前缀与bonus的语义。深度选择依据拟合/校准范围内获得的接受与成本证据，比较总时间除以总有效推进步数；验证与完整chunk成本、闭环质量另报。禁止用已暴露全量面板反复选深度后称其独立TEST。

## 动态分叉的候选评估范围

用户继续要求把中心点与正负偏移的距离用于选择“仅中心”或“双分支”的方向加入交接。已确认的是研究这种按节点决定是否分叉的路由，尚未选定阈值、单调规则或部署方案。接手会话应在与实际验收一致的动作空间、实际步长及数值边界下定义分支距离，核对中心候选的真实target误差与后续前缀覆盖，并通过适用的CAL选择和冻结路由规则。

候选路由只决定提案拓扑，所有提交仍按原target验证和合法前缀/bonus规则执行。中心与偏移的原始输出不预设为校准过的接受概率或不确定性；相关推导与诊断留在交接内容，不能写成“小偏移保证接受”的约束。拓扑变化、动态batch、路由与同步成本应纳入同一有效推进成本比较。

用户本次要求向正在负责投机的会话交接问题与修正目标。本会话只维护交接和记忆；新实现、训练、CAL和GPU评估由接手会话按适用授权与资源登记推进。旧冻结实现、全量结果和失败保留；本条不把尚未测量的尾部、动态深度或分叉方案记为已采用或提速成立。
