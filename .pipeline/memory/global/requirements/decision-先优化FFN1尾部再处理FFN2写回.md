# 先优化FFN1尾部，再处理FFN2写回

本轮M39继续按已说明的顺序推进：先验证FFN1尾部工作分摊，再针对FFN2写回和设备函数保存恢复开销做有限优化。直接在optimized中迭代；先验证原有数值与状态契约，再与原Torch同边界比较。原累计10小时上限、历史截止、负结果和科学权限保留。

“更快完成行块是否能解决问题”仍是用户提出的研究问题，不是已经成立的结论，也不是固定采用某种分块形状的要求。具体分块由依赖与实测决定；本条只记录用户确认的推进顺序，不扩大至机器人评估或额外预算。

尾部分摊之后，用户确认先单独尝试FFN2写回中减少重复索引/读取及四元素向量化，再检查设备函数保存恢复；每项先核对数值和状态，再看完整层及独立FFN相对原Torch的结果。不能以全部内联或继续细分tile替代单因素验证。具体实现收益仍须实测，不写成长期事实。
