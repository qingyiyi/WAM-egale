# 回到阶段同步版，先重新做顶层规划

用户要求将当前optimized恢复为此前逐阶段全局同步的已验证版本，保留本次ready调度源码、精度/性能和失败证据；随后先讨论顶层设计，不继续直接迭代现有细粒度ready队列。

下一步规划需区分数学tile、调度任务、CTA的数量和职责，讨论更大分块及可合并任务，再决定实施路径。此决定不将任何特定分块大小或融合组合视为已批准结论，不自动启动新的GPU实验。仍限定单层完整Transformer，baseline、投机侧、原tile和保护HW文件不动；旧预算、截止和负结果保留。

## QKV交错派发留到统一依赖图设计阶段

用户明确当前先讨论顶层调度，Q/K/V按行块交错的顺序留到后续完整任务依赖图设计阶段统一考虑。暂不单独实现或试跑上一轮助手提出的QKV交错顺序。此顺序适用于本Cycle的M39，不改变已采用的投影计算体、数值边界或现有阶段同步。

用户关于入度为零任务的派发及静态/动态调度的提问仍属方案讨论；不据此把通用动态队列、某个优先级、具体tile粒度、GPU运行窗口或全面去同步写成已经确定或获准执行。已有累计预算、原截止、保护边界与旧负结果保持。

## 2026-10-25：FFN 两阶段先保留同步

用户确认下一实现方向为 FFN1+bias+GELU 写入 global ACT，然后暂时进行阶段全局同步，再执行 FFN2+bias+gate/残差；以后单独讨论移除该同步。FFN1 没有残差相加，残差位于 FFN2 输出端。原 BF16 舍入与 FFN2 七段有序递推不变。

用户随后批准实现两阶段同步版并测试、输出完整阶段表，再据结果优化。实际实现与采用状态按 Cycle/Experiment 读取；原 A 独立保留，不沿用旧测量宣称新阶段边界已验证。本决定不确定统一 warp 比例、tile 大小或新的 DSM 方案，不将“同属 GEMM tile 任务”解释为所有计算共享相同参数或数值归约。旧负结果保留。

## 2026-10-25：只在 FFN1 内尝试专职 warp 流水

用户明确批准先在 FFN1+GELU 尝试 1 个 TMA warp、4 个 MMA warp、3 个 epilogue warp。当前 FFN1/FFN2 阶段全局同步保留，FFN2 七段舍入与计算不改；通过真实输入精度及完整层对照决定是否采用，不预设该比例最优。此为 M39 本轮实现边界，不扩展为所有阶段的统一分工。具体 tile、握手及性能为实验设计/结果，按本轮 Experiment 读取。
