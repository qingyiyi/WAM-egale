## 已确认的修正与尚未确定的部分

前一轮只改变设备函数组织，固定tile/算术/sync，整层下降9.46%–10.87%；SASS显示旧逐tile通用函数带大量入口/出口保存，而新阶段函数把tile循环包在内部。控制实验支持设备函数组织是原Cross退化的重要因素。

旧独立585–594µs来自旧独立编译路径；旧整层约790µs也来自改动前版本。当前专用函数在独立和整层都使用相同callee，独立也带其函数边界成本。不能拼接旧独立最优数值与新整层，继续声称当前还存在同样的大额“集成惩罚”。

这次调用点时间戳包含专用函数入口/退出；前轮609/607µs是在函数体内打点，不能将数值上升说成新回归。未插桩整层控制变化约±0.2%以内。

尚未把每个微秒精确拆给寄存器保存、指令选择、访存、队列与屏障；没有动态NCU硬件counter。不宣称已经确认唯一硬件根因，不把等待总和当可兑现收益。

## 官方机制参考与推断边界

CUDA的local memory是线程作用域的内存空间，不是片上寄存器；编译器可因大对象、索引或寄存器不足使用它。该一般机制来自[NVIDIA指南](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#local-memory)，不能替代本项目动态测量。
寄存器/shared对驻留的约束可参考[NVIDIA内核资源说明](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-cuda-kernels.html)。本次两臂静态驻留同为1CTA/SM，因此没有证据把当前差距归因于独立→整层CTA驻留数下降。
