# 简易版逐阶段原版/独立/嵌入对照

A=冻结原版数学函数的独立阶段（来自baseline源码的测量副本）；B=简易版同阶段独立cooperative kernel，保持108CTA/256线程及98848B共享workspace；C=简易版测量副本内的阶段区间。全部来自同一真实fixture中间量，未随机造输入。B不另外搜索最优grid/tile。

A/B各两进程×8次AB/BA交错CUDA Graph replay，前后globaltimer marker；空marker间隔中位数分别1.024/1.536µs，未扣除。C每进程4次完整层内部globaltimer。C含队列、同步及不同缓存历史，且插桩改变编译资源；不能将C/A解释成纯算术比，不能相加表中中位数替代普通完整层计时。小于数微秒的差异须考虑marker量化。

30个登记阶段×三KV；B14 cache_insert没有KV写入，A/B为N/A，但整层阶段同步仍在C中计入。其余29阶段×三KV×两进程的原版/自有输出有限逐位通过；全部有效KV保持。self-attention的A包含原版两个KV pack kernel及FA2，布局另计；没有漏掉materialization。

单位µs；数值为跨两进程全部样本的中位数。资源[CTA,每SM可驻留CTA上限,shared bytes,register/thread,local bytes/thread,threads/CTA]来自CUDA静态属性，不是NCU实测occupancy或流量。

## 解释与下一步

OBSERVED：cross K/V独立GEMM仅约1.09–1.10倍原版；FFN1约1.83–1.84倍，不能把全部GEMM一概当成已经对齐。cross-K RMS独立约3.37–3.55倍；table约4.93–5.13倍；GELU约5.90–6.07倍；layout约20.7–35.7倍。长KV self-attention独立约1.08倍（含原版pack），cross-attention约2.49倍。

OBSERVED：普通简易整层255register/thread、1624B local；插桩整层255/1600。独立table为40register、0local，cross-K RMS70/0，GELU34/0，cross-K254/0，attention255/848。相同设备函数嵌入不同kernel的编译资源并不相同。NCU仍无权限，不能据静态localSizeBytes宣称动态spill字节数。

HYPOTHESIS：pointwise目前只有四warp执行且承担动态op/索引与tile队列开销；layout由一个线程顺序扫描；Norm逐行转FP32、归约与单warp回写；attention地址适配与固定整层资源可能拖慢。这些结构能解释优化方向，但每一项的独立贡献尚未做单因素测量。

RECOMMENDATION：先改pointwise并行组织与B14只读layout；再改cross-K RMS数据路径、FFN1与cross-attention；最后做跨阶段ready填尾波。每次改变归约或BF16边界前须重新验证。仅移除全局同步不保证对齐原版。不要把独立stage时间相加或将理想消除的差额当作实测整层加速。
