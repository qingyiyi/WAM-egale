# WAM 单个 Transformer block 局部 warp 流水判定任务

日期：2026-10-23。所有计划、日志和报告使用北京时间（Asia/Shanghai）。

你是服务器上的 Codex。本任务要求在已有 WAM 算子工程中实际执行一轮有界研究，完成代码、验证、测量和可复核报告。不要停在建议或设计草案，也不要把本轮扩大成完整 block 通用调度器重写。

本轮要回答两个问题：

1. 主线：在保留 FFN2 现有四 warp MMA、tile 和数值顺序的情况下，其余四 warp 能否提前准备当前 tile 的独立后处理数据，获得完整层净收益？
2. 副线：LN1 与其后调制的局部融合，能否以较小改动减少中间访问和阶段等待？只有该模板通过准入且无可信整层退化，才扩展到 LN3。

本轮完成的标准是得到可重复的结论。负结果、收益低于噪声、只有机制收益而无完整层收益，都可以是合格结论。不要为了得到正结果不断扩大范围。

## 5. T2：实施一个受控的 FFN2 分工实验

### 5.1 结构约束

保持：

- 原 W3–W6 四 warp MMA。
- 原 tile、两段 K7168、原 CUTLASS cp.async 输入流水。
- 原第一段 BF16 partial、第二段合并与最终舍入顺序。
- 当前数学语义和候选隔离。
- 原任务队列及第一段发布粒度。

另外四个 warp 尝试提前准备当前 tile 的独立数据。第一版不额外设专职 copy warp。

原 commit 是八 warp 协作提交。若新版本由四 warp 提交，要明确这是改变了 epilogue 并行度；若仍由八 warp 提交，要说明准备数据如何交接。两种方式只选一个最有依据的首版，不同时广泛搜索。

不要把整个 128×128 的 residual、gate、partial 全部预存而不做资源预算。优先使用少量必要状态／片段。任何额外 shared 或寄存器保留都要记录，并解释与正在执行的 mainloop 是否冲突。

数据 ready 和缓冲 free 是两种不同条件。不得覆盖消费者仍在读取的区域；不得让部分 warp 跳过要求全 CTA 参加的 barrier。重复 Graph replay 时也必须正确初始化和推进状态。

### 5.2 比较 A、B、C

- A：原始固定锚点的独立编译产物。
- B：新角色、新数据布局和缓冲，但串行执行准备与 MMA。
- C：与 B 尽可能相同的角色、布局、缓冲和编译资源，允许准备与 MMA 重叠。

严禁把 A 也放进已经新增大量分支的新大 kernel，再称它为未受影响的旧基线。新分支即使不执行，也可能改变整个 kernel 的资源和布局。

B/C 尽可能仅改变执行／交接顺序。若编译器重排、消除、额外同步或资源差异使控制不纯，记录这种限制，不声称得到了完全干净的因果分解。最终是否采用始终以无插桩完整层 C/A 为依据。

### 5.3 正确性先行

复用现有正确性体系，保持当前项目的逐位要求或此前明确批准的标准，不放宽 eps、容差或状态要求。

实际运行多少签名、多少结构变体就报告多少，不复制历史通过次数冒充本轮结果。重点检查：

- 输出、FFN2 partial 和最终门控／残差等受影响中间量。
- 原输入未被意外改写。
- 有效 KV、候选 private KV、RNG 及重复执行状态。
- 正常与 debug 路径。
- 连续多次 Graph replay 的旧标志、缓冲复用和未完成读写。
- 当前框架要求的必要 B2／cold fallback 回归，不另造无关的大型测试工程。

发现 correctness 失败时，该变体不进入性能采用判断。允许一次有明确定位的局部修复；不能以放宽数值要求消除失败。

### 5.4 测量与决定

- 正式计时使用无插桩产物、完整单层 warm CUDA Graph、三个 KV 点。
- 使用已有交错顺序测量框架，至少两个独立进程确认候选方向；预热／回放／样本量沿用已验证方案或给出调整理由。
- 报告各 KV 的绝对耗时、延迟比 t_C/t_A 与 t_C/t_B（越小越好）、配对差、波动和各进程方向；若另列加速比，明确使用 t_A/t_C，避免方向混淆。
- 不通过选择性删除慢样本、改变时钟或跨轮乘加速比构造收益。
- 不知道部署 KV 分布时，不编造加权平均代替逐点结果。
- 收益是否可信以本轮噪声与复现为依据，不设置“低于 1% 一律失败”或“快 0.2% 就采用”这种机械门槛。
- 只有追加测量可能改变决定时，才在预算内追加一次确认；不要为追求显著不断重复。

结论至少分为：

- NET_GAIN：C 对 A 的完整层净收益可信，正确性通过。
- MECHANISM_ONLY：C 对 B 有改善，但对 A 没有可信净收益。
- NO_GO：正确性／资源／竞争／收益上界提供了明确反证。
- INCONCLUSIVE：分辨率、噪声或环境不足以判定。

分类按 KV 点分别记录，再给出采用决定。若三档 KV 收益方向混合，保留为条件候选并明确适用点；没有部署分布或既定取舍依据时，不用平均值掩盖超过噪声的退化，也不全面替换 A。本轮不为此新建复杂运行时派发机制。

主线默认一版、最多一次有明确证据的局部修订。任何结论都保存原始数据、源码身份、资源报告，并打印完整阶段表。失败或不确定时保留 A 为当前采用版本。

- 保留原 LN 归约树、eps、FP32 运算顺序及原 BF16 输出边界。
- 保留 scale／shift 的广播、FP32／BF16 temb、单 token／逐 token 等现有合法分支。
- 一行 norm 完成后直接做该行调制。仅在确认没有其他消费者后，普通路径才省略对应 FP32 中间张量读写；debug 仍提供已有审计能力。
- 保留真正需要的行内归约同步和后继 GEMM 输入就绪关系。
- 不为这项改动重新安排八 warp GEMM 或引入新 ready 队列。

完成 LN1 后先做现有正确性准入和独立于 A 的完整层比较，打印完整阶段表。

只有 LN1 模板通过准入、没有可信整层退化，且预算允许，才扩展同模板 LN3；LN3 作为独立增量再次比较并打印阶段表。LN1 不成立时不机械继续 LN3。

不承诺融合必然有收益。若当前已有等价试验，先复核适用性，避免重复。

## 7. T4：最终复核、采用与收口

### 7.1 最终同轮比较

只组合已通过判定的候选。若主线与副线都成立：

- 比较 A、FFN2 单项、融合单项、二者组合。
- 最终保留实际更优的版本，不假设单项收益可以相加。
- 在公平条件下同轮加入 D，以及已存在可用的 G。
- 若无候选通过，A 仍是有效最终结果，完整记录为什么未采用。

组合产生新的源码／二进制身份，需完成与组合风险相符的正确性和资源复核。不要无理由扩大测试范围。

### 7.2 哪个时点回来讨论

达到以下正常完成状态后，结束本轮，返回报告：

- 主线已有 NET_GAIN／MECHANISM_ONLY／NO_GO／INCONCLUSIVE 结论；
- 副线已完成或明确说明跳过／受阻原因；
- 完成当前保留版本的完整层复核；
- 有完整阶段表、固定源码／二进制身份和可核对原始数据。

以下情况应提前收口：

- 达到 48 小时或 GPU 窗口上限；
- 出现无法在一次局部修订内解决的正确性／资源问题；
- 继续推进需要改八 warp GEMM、拆 FA2、改 tile／CTA 数、改第一段发布粒度或引入跨阶段调度；
- 只有人工加长 tile 流才能看到收益，当前真实形状没有可信收益；
- 访问／环境缺失使剩余实验无法完成。

不需要每改一个 helper 就让用户回来讨论；也不要为了“整个 block 都流起来”越过本轮边界。

### 7.3 下一轮只是待讨论方向，不在本轮自动实施

根据本轮结果，下一轮再决定：

- 如果 FFN2 有净收益，能否把同样的协作与交接方式迁移到其他具体区间。
- 如果只有融合有效，继续局部 owner 内融合还是转向跨 CTA 的行组就绪。
- 如果两者均无可信收益，是否把重点转向当前小投影核心、实际关键路径或强基线差距。
- 只有出现足够的合法并行工作与净收益空间，才展开更完整的 ready 调度设计。

- CURRENT_MEASURED：本次当前产物已经实测。

- 不能把历史耗时无标记地搬进新版本。

## 10. 执行风格

- 先讲当前观察、决定和下一步，不用长篇复述背景。

- 采用一个清晰、可读的局部实现，避免为本轮试验引入通用框架。
- 做到本轮判定程度就收口。下一轮是否扩大固定 warp 分工或跨阶段调度，由带回的证据再讨论。
