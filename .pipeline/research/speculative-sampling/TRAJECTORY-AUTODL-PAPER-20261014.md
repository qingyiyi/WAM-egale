# 轨迹指标、AutoDL租卡与中文稿启动

2026-10-14，Asia/Shanghai。范围：投机采样主线。此次只查论文、官方文档和已有日志，未使用本地GPU、未训练或运行新任务；本地命令限制CPU 0一个核。用户偏好是尽快得到可信算法结论，H800也可接受。

## 1. 是否必须保持trace长度不变

**不必逐条完全相同，但仍应测量并控制任务效率。** 本项目的trace长度是环境执行步数，不是去噪迭代数，也不是末端执行器的空间路程。对于改变近似推理算法的研究，成功率和完成任务的成本才是最终目标；同一任务存在不同有效动作序列。短一些且成功不是坏事，长一些是否可接受取决于总耗时、控制预算及尾部表现。

这与只改内存布局、缓存或CUDA实现的工程优化不同。后者应先在同一算法、同一输入和同一硬件上通过严格数值控制，不能借“允许轨迹变化”掩盖算子错误。本项目也不能声称目前阈值接受规则保持target分布或同seed轨迹。

### 后续评测建议（尚未替换历史标准）

1. 固定环境、成功判据、最大步数、控制频率、相机、动作chunk执行长度、模型权重与噪声设置。按任务/初态配对T和候选；分离训练、阈值校准和最终测试。
2. 主质量指标为全部计划回合的成功率，报告分任务结果、配对差与置信区间。正式非劣性容差及所需样本量须在最终测试前确定，不能用4个样本证明“成功率不降”。
3. 同时报告单次policy延迟、完整任务wall-clock、reset/冷启动、policy chunk数、环境步数。算法质量测试可并发；用于论文的速度测试另开无争用时段。
4. 环境步数与完成时间优先做T和候选共同成功子集的配对比较，列出子集大小、均值/中位数、分位数与最长回合；同时列出各自成功全集和失败/超时，防止只挑容易成功的任务。失败记满horizon的penalized steps可作为补充，不能代替成功率。
5. 步数容差可由任务需求预先指定，也可作为完整成本分析的次要指标；没有文献为本项目给出通用的“平均5%、最坏10%必然安全”。旧实验仍按旧门槛解释，不能放宽标准后回填为通过。

当前16回合四臂pilot中，MSE相对T的步数较好，但相对WL2丢失一次成功，原双参照门未通过；WL2/RES也有步数尾部问题。它们仍是开发结果，不因本次指标讨论而晋级。原始表见[接受器对照](ACCEPTANCE-COMPARISON-RESULT-20261014.md)。

## 2. GPU是不是主要瓶颈

**GPU是policy推理的重要因素，但现有证据不能把整个实验归为纯GPU瓶颈。** 对历史12条完整任务计时重新求和如下；它们是已有开发回合，并非新做的硬件性能基准。

| 已记录阶段 | 合计秒数 | episode elapsed占比 |
|---|---:|---:|
| policy RPC | 1767.426 | 48.94% |
| reset RPC | 1502.961 | 41.62% |
| cache RPC | 112.549 | 3.12% |
| RPC之外的剩余时间上界 | 228.493 | 6.33% |
| elapsed合计 | 3611.428 | 100% |

另有约78.771秒环境构造/关闭开销在上述elapsed外。policy RPC包含CPU提交与通信，不等于GPU忙碌时间；reset也不能全部归为CPU。源码确认当前offload模式将文本编码器放在CPU，而reset还涉及其他准备工作，尚未完成子阶段归因。因此不能据此声称“42%全是T5”或“仿真只占6%”。

条件示例：如果**只有policy RPC减半，其余完全不变**，这批任务的总体加速为 `1/(1−0.4894+0.4894/2)≈1.324×`。这是Amdahl计算，不是H800实测；若换卡同时改变reset等阶段，该示例不适用。

下一轮先记录冷启动、文本编码、缓存准备、视频分支、action verifier、环境/渲染的分段耗时，再决定将时间投入换卡、初始化复用还是verifier优化。小MLP的训练不是目前已有日志展示的主要任务耗时；更大卡是否加速新训练仍需测量。

## 3. 为最快第一轮结果租什么卡

**首选整卡A100，推荐80GB；40GB已有本地运行基础。预算允许时，可用两张A100分片跑独立任务。H800留作完成适配后的候选。** 这是结合本项目代码的时间到结果判断，不是声称A100硬件算力高于H800，也不是已测得双卡线性加速。

关键原因在[共享KV CUDA源码](../../../投机采样/experiments/shared_prefix_torch_v2/csrc/shared_torch.cu)：运行时要求 `major==8 && minor==0 && multiProcessorCount==108`；[编译入口](../../../投机采样/experiments/shared_prefix_torch_v2/setup.py)默认只指定架构8.0。H800不满足此合同，不能原样运行当前优化路径。NVIDIA也说明[Ampere cubin与Hopper的兼容条件](https://docs.nvidia.com/cuda/hopper-compatibility-guide/index.html)：跨大版本架构不能假定原生cubin兼容，需合适PTX或重新生成代码；本项目另有显式运行时限制，单纯换编译参数仍不够。

| 选择 | 本项目判断 | 建议配套 |
|---|---|---|
| 1×A100 80GB整卡 | 第一轮优先；减少架构迁移，显存余量较大。80GB本身不保证比40GB快 | 至少16 vCPU，优选32 vCPU；128GB RAM；约200GB可用SSD起步 |
| 2×A100 40/80GB整卡 | 时间优先时用于独立任务分片，不做跨卡模型并行；先验证单卡再扩展 | 32–64 vCPU、约256GB RAM；每卡先两个独立EGL worker，观察实际吞吐 |
| H800 80GB | 有潜力，当前不能即插即用；需隔离移植共享KV并通过同卡数值控制，或先验证原Torch算法路径 | 同样需要足够CPU/RAM；不得把A100上的T与H800候选直接当配对比较 |
| 24GB消费卡 | 不作为此次省时间首选：容量余量及当前专用算子兼容性都要处理 | 不为省显存擅自改变精度、模型或去噪步数 |

这些CPU/RAM/磁盘数值是工程配置建议，不是已测得最低需求。现有supervisor每个模型worker设置7个CPU线程；两worker还要运行模拟器、渲染与RPC，低CPU配额可能抵消GPU升级。AutoDL[官方选型说明](https://api.autodl.com/docs/gpu/)指出市场展示CPU/RAM为每GPU配额，随卡数分配，选机时应看完整配置。其[Pro规格文档](https://www.autodl.com/docs/instance_pro_api/)列有H800，但这不代表此刻有库存，也不代表本报告核实了实时报价。

历史显存采样提供容量参考：完整数值校验进程最大采样约21.83GiB；质量模型worker各自约13.75–14.20GiB；无外来进程的整卡样本最大约30.23GiB。采样不等于精确峰值，也不能保证任何任务都放得下；支持先选40/80GB，而不是赌24GB刚好够。来源和复算记录见[证据JSON](../../../review/OMISSIONS.md)。

## 4. SSH验证如何落地

AutoDL支持[SSH自定义端口与公钥登录](https://www.autodl.com/docs/ssh/)，技术上可远程开展。当前未租卡、未连接远端、未运行收费任务；需要实际实例地址/端口/账号和可用的公钥登录，随后按明确的任务批次与时长上限执行。不要在聊天中传私钥。原本本地GPU预算不自动视为新的无限租卡授权。

迁移方案如下，属于下一阶段工作，未实施代码修改：

- 以当前环境为对齐目标：模型侧Python 3.12、PyTorch 2.9.0+cu126、transformers 4.55.2、numpy 1.26.4；仿真侧Python 3.10、MuJoCo 2.3.7、robosuite 1.4.0及现有LIBERO版本。镜像选Ubuntu 22.04 x86_64及兼容CUDA 12.6的驱动/开发工具链。使用独立环境，不依赖默认镜像刚好兼容。
- 只迁移投机代码的必要依赖、冻结checkpoint、LIBERO资产/初态、所需teacher数据和选定数值fixture。保留来源哈希与配置；不搬整个历史目录，不接触tile方向。现有绝对路径和旧job冻结信息要在新远端job内适配，不能把已关闭job改头后重跑。
- A100必须核对完整SM80/108SM设备，不能选会改变该合同的MIG切片。重新构建/加载后，先跑原T和同算法Torch/共享路径的短长KV完整chunk控制，再跑完整任务。即使同架构，也不把旧硬件结果当新环境验证。
- 若选择H800，先独立处理编译、设备合同与数值对齐；不只删掉device guard。原Torch路径可作为算法质量验证备选，但同样要检验树、scheduler、路由、cache与RNG，且不能借此声称已验证共享KV速度。
- T与候选在同一远端硬件/软件配置中配对。质量筛选可并发、共卡，分别记录异常；速度结论需要另做隔离计时。先每卡两个EGL worker，不因80GB余量大就直接提高到四个。
- 第一批短而有界：完成环境/数值控制后，先8个完整回合估计episodes/hour和reset占比；随后可用10任务×2初态×2臂=40回合作为筛选例子。任务/初态划分须避开训练/校准泄漏；若任务本身已用于draft训练，应明确是已见任务的新初态测试，并另列未见任务，不能将10个任务都称为未见任务。它仍不自动构成成功率非劣性证明。正式样本量由容差和统计功效决定。

进一步压缩reset可能比追求最高GPU标称算力更有效，但常驻模型服务、缓存文本等改动必须验证每回合reset隔离、无状态泄漏和噪声语义，不能直接跳过reset以获得漂亮速度。
