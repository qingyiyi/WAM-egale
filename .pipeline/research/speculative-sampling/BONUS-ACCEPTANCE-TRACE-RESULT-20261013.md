# Bonus、接受率与环境轨迹：完成质量先行的开发试验

结论：研究默认候选已设为 **bonus ON + depth_then_cost + A_off + 共享 KV + O1/O2/O3**。保持原阈值、七个验证节点和每块完整 50 步降噪。新选路提高接受率并通过这轮轨迹门槛，**还没有测量新的加速比**。

LIBERO-10 task0，init3/4；每臂两个完整任务，两轮交叉分配、两个并行 EGL worker。原始 T 和旧 OFF/BONUS 使用已封存的同初始状态质量证据；本轮 GLOBAL 重现旧 BONUS，历史耗时不作为本轮测量。

## Bonus 与两种“步数”的关系

- 接受深度为 0：回退到已验证的 root target，实际推进 1 次降噪更新。
- 接受深度为 1：接受第一层 draft，再用父节点 target 回退，实际推进 2 次。
- 接受深度为 2：接受两层 draft，加上已经算出的叶节点 target bonus，实际推进 3 次。

所以 bonus ON 的平均推进是 `1 + P(首层接受) + P(两层接受)`。每块仍完整提交 50 次降噪更新，包括最初的 target anchor 和末尾不足三步的普通 tail；bonus 改变验证轮数，不减少总降噪步数。

环境轨迹步数取决于生成动作、环境状态和完成任务所需时间。首块通常提交 12 个动作，后续块通常 16 个，最后成功块可能提前结束。接受率提高没有“环境步数必然降低”的单调保证。本轮虽然少了 6 个环境动作，两组都调用了 38 个 chunk，因此不能期待模型耗时按环境步数同比下降。

## 新选路为什么有帮助、为什么帮助有限

原 global 先选择 `first_cost + second_cost` 最小的路径，再检查两个边各自是否在阈值内；这可能选择一个会回退的路径，同时另一条路径两层都能接受。新策略先最大化阈值内可接受深度，再沿用原总误差与节点次序。没有扩大阈值，也没有增加节点或模型前向。

4,096 组穷举证明：同一棵树的可接受深度不会下降；深度相同则保留原 global 路径。**该保证只针对同树，不保证改变轨迹后的所有后续树都更易接受。**

新候选 init3 与原路径相同；init4 在 chunk5 和 chunk16 两棵树上改变选路，局部推进分别由 2→3、1→2。chunk5 原路径首层误差 0.006415、次层 0.007869，后者超出阈值 0.00783968；另一条路径的两个误差分别 0.006819、0.007818，都通过原阈值，因此可以提交 bonus。后续访问状态和接受统计随之变化，不能把总共少了七棵树都视为两次选路的直接节省。

旧版 171 份 trace、4,600 棵树的存量成本反事实中，也仅 4 棵能多接受一步；它们来自旧 draft / bonus OFF，不能冒充当前实验。当前 GLOBAL 实际只有 1 棵可改善；DEPTH 自己访问的树上记录到 2 棵机会，说明选路空间有限。

## 拒绝集中在哪些阶段

按实际 scheduler sigma 分三个诊断区间；这些区间只用于统计，验证阈值没有分段修改。

| DEPTH 的 sigma 区间 | 树数 | 首层接受 | 两层完整接受 | 平均推进 |
|---|---:|---:|---:|---:|
| 高：sigma ≥ 2/3 | 38 | 0% | 0% | 1.000 |
| 中：1/3 ≤ sigma < 2/3 | 99 | 27.27% | 2.02% | 1.293 |
| 低：sigma < 1/3 | 595 | 92.10% | 87.23% | 2.793 |

高、中区间贡献了 110/157（70.06%）的首层回退。首 chunk 完整接受率 80.56%，后续 chunk 为 70.69%，因此不能把问题归为首 chunk 过慢。主要改进方向是高／中 sigma、后续真实访问状态下的 draft 预测，而不是单纯增加 draft 层数或放宽阈值。现有 draft 是 25,928 参数的双头方向 MLP；本轮没有更新模型权重，也没有证明这些拒绝来自哪个特征缺失，训练原因仍需验证。

## 正确性与完整性

- 12 对 CPU 完整 50 步 BF16 对照：两个 selector、首/后续块、三档阈值；同注意力后端的输出、KV、调度器、RNG、接受记录一致。不能将其表述为所有 CPU 注意力后端都与原始 Torch 位级一致。
- 两份真实长 KV 状态，共八个完整 GPU chunk：原始 Torch 与共享 O3 对两个 selector 的输出、全部 30 层有效 KV/元数据、调度器、RNG 和选路一致；GLOBAL 还重现了旧 bonus GPU 数值输出。
- 四个完整 episode 无截断，逐个验证实际 NVIDIA EGL。GLOBAL 的 112 对存档张量、实际动作命令、初末环境/控制器状态、RNG 与计数全部重现旧 BONUS。每块接受记录与原始 chunk 环境事件对应，覆盖全部 76 个 chunk。
- 全部 GPU 进程已退出，NVML allocated 显存为 0，compute/graphics 进程为空；原代码、受保护 HW 文件及既有记录不改写。

## 失败记录与预算

首次 GPU 诊断因 teacher OFF 时不存在 `_p0_teacher_context` 而在第一块停止，未获得有效对照。已完整封存 v1；实际进入 23 次前向，但未正常封账，因此保守计入 640 次预留和 61.885 秒。v2 的私有记录器直接读取请求上下文，新增缺失 teacher 属性的 CPU 检查，再执行独立有限计划。

最初 CPU 检查的观察器安装次序失败记录也保留。GPU 完成后的第一次离线分析读取了错误的事件字段 `done`；真实 schema 是 `done_after_chunk`，已在独立 CPU 审计副本中修正并保留原冻结代码，未重跑 GPU或改写运行数据。可复现入口为 evidence/analyze-schema-corrected.py。

本次成功采集 913.177 秒、3798 次目标前向；累计（包括保守失败预留）46654 次、14118.698 秒 = 3.922 小时，低于用户批准的 5 小时；剩余约 64.7 分钟。新任务 5 个模型启动、4 次 EGL 初始化，没有覆盖旧计划或删除失败。

## 下一步

1. **先扩大质量检查**：保留当前 bonus/DEPTH 候选，补未用于这次选择的任务/初始状态，始终同时保留原 T、旧 OFF 对照，检查成功率和轨迹尾部。两个开发状态不足以完成质量确认。
2. **接受率专项改进**：采集 bonus ON 下高／中 sigma 的真实 root/parent target 标签，固定阈值和 50 步，从拒绝阶段的 teacher 对齐入手训练 draft。现有线上 B_on 检查点曾有失败，不能直接替换 A_off。仅提高统计接受率、不改善成功率/轨迹的版本不提升为默认。
3. **质量稳定后确认速度**：关闭本轮选路/环境诊断，以单部署模型的完整 policy/chunk 延迟为主，覆盖首块与短/中/长 KV，保留 draft/验证/回退/bonus/host 开销；另以完整 LIBERO 任务检验包含 reset、环境执行的 E2E 指标。调用数下降与本轮诊断耗时都不作为加速比。
