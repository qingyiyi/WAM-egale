## 1. 当前模型与一层 Transformer

当前 A_off 的网络是 `227 → 51 → 51 → 224`，两个 SiLU，25,928 个参数。227 维输入由当前动作去噪状态 112 维、上一实际使用 direction 112 维，以及 sigma、next_sigma、timestep/1000 构成。112 对应 7 个有效动作通道 × 16 个动作位置。模型没有直接读取图像、文字或 target 中间特征，上一 direction 携带的是间接条件信息。

224 维输出拆为 center 与 delta，各 112 维；产生 center+delta 与 center-delta 两个残差，反归一化后加上一 direction。因此当前已经是**一次前向、联合训练、输出同一个降噪步的两个候选**。center±delta 可表示任意一对向量，不应将该参数化本身误判为表达能力限制。

证据：[MLP 与预测输入](../../../投机采样/scripts/p0_batched_verify.py)、[实际 checkpoint 审计](SPECULATION-DRAFT-COST-ANALYSIS-20261013.md)。

仓库并非从未比较 Transformer。历史 task8/9 的 75 个 chunk、1,800 个 paired anchors，在固定旧阈值下得到：

| 历史训练版本 | MLP 两层全接受 | Transformer 两层全接受 |
|---|---:|---:|
| Phase4 | 89.61% | 88.50% |
| PhaseA | 90.33% | 90.67% |

这是旧 context 模型的 candidate-state shadow replay，没有新的任务执行；不能与当前 A_off / bonus 的 71.17% 直接横比，也不能推出一层 Transformer 无效。Phase4 存档 Transformer 是 2 层、宽度 128、4 heads、FFN 512、context_window=8、583,136 参数，与当前小 MLP 不是等规模对照。见[历史报告](../../../投机采样/results/analysis/p0-d-compare-candidate-shadow-20261008-r1/pooled_candidate_shadow_report.md)及[配置](../../../投机采样/results/draft_full_phase4-20261007-f32/models/action/transformer/result.json)。

一层 Transformer 值得测试，但应控制变量：相同数据、输入信息、归一化、双候选接口、训练预算和阈值；另设适当加宽的 MLP，避免把增加容量当作 attention 的贡献。可把当前 16 个动作位置表示为 16 tokens，每个包含该位置的状态和 previous direction，加入位置及 sigma 编码，用一个小型 attention+FFN block 输出两组残差。将整条 227 维向量视为一个孤立 token 不会获得位置间 self-attention 的作用。

历史去噪步作为 tokens 是另一个设计，不能与动作位置 tokens 混为一谈。额外加入已有 target / 视觉语言缓存特征也应单独消融：模型结构与可见条件信息同时变化，无法解释收益来自哪里；更不能引入每次重新运行大视觉编码器的成本。

[EAGLE，ICML 2024](https://proceedings.mlr.press/v235/li24bt.html)使用单个 Transformer decoder layer，并复用 target 特征；[作者原文 §3.1](https://arxiv.org/html/2401.15077)支持这一结构经验。对本项目的推断是“小 attention 模块 + 有信息的条件”值得比较，不是它已证明适合当前连续 direction 问题。

## 2. 如何训练并控制成功率、环境步数

当前续训损失为 `min(head MSE) + 0.10 × mean(head MSE) + 0.01 × relu(0.05 − normalized_head_gap)`。最后一项鼓励两个候选保持间距。它优化 direction MSE，而现用 gate 检查乘以 scheduler 步长后的状态 L2；也没有直接约束完整动作或任务轨迹。见[训练实现](../../../review/OMISSIONS.md)。

推荐依次验证：

1. **冻结 target，保留当前 A_off。** 汇集原教师轨迹和 bonus ON 实际访问的 root、两条 parent 状态。标签必须由 target 在相同 state、sigma、视觉语言/KV 条件、CFG 与有效动作投影下计算。不能拿纯教师轨迹上另一个状态的方向当作当前 draft 状态的标签。
2. **覆盖第二层的真实输入。** 让 draft 先走一步，再对它实际到达的状态取教师标签；训练时包含这种输入，并保留教师状态样本。当前 verifier 已计算 root/parent target，可以设计低扰动导出；现有记录是否包含全部训练所需张量需先审计，不能仅凭有误差日志声称可直接训练。
3. **按拒绝阶段诊断与采样。** 当前两条开发 episode 的高 sigma 38 棵树全拒绝，中 sigma 两层完整接受 2/99，低 sigma 为 519/595。优先补高/中 sigma 数据，同时保留低 sigma 质量。它们只是诊断分组，不能直接用来确定三档阈值，也不能仅凭这两个 episode 判断容量或条件信息是根因。
4. **损失逐项对齐。** 首个消融采用 `L_step = ||Δsigma × (d_draft − d_target)||²`，与现用 gate 的平方一致；保留适度方向拟合项，防止单纯步长加权忽略其他阶段。再比较短段递归与完整 chunk 动作一致性监督。若使用物理动作尺度或分通道权重，应明确它是新度量，重新校准阈值。
5. **检查多样性是否有用。** 对固定完整条件与输入，确定性 target 的方向只有一个；两个头的价值应来自较高的真实候选覆盖率。先比较有/无强制间距项，不假定拉大两头距离一定提高接受率。单候选可先做离线诊断，在线缩树另立实现对照。

[EAGLE-3，NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/c7b5a35ea98b62512a869c19ea7b03cb-Abstract-Conference.html)在训练时将 draft 自己的输出回填为后续输入，见[作者原文 §3.2](https://arxiv.org/html/2503.01840v3)。可以借鉴训练与推理输入一致的思想；连续去噪必须在预测状态重新查询 target，不能直接照抄离散 token 的标签机制。

**任何上述 loss 都不能单独保证完整任务成功率或环境步数不变。** 降噪局部误差、最终动作偏差、接触与抓取后的环境变化之间没有现成保证。bonus 的 target 更新在已经接受的近似状态上执行，也不会自动把状态恢复为纯 target 的原轨迹。

质量筛选采用按完整 episode / 初始状态分组的数据划分；若要声称跨任务泛化，还必须留出整个任务。调参状态与最终测试状态分开，不能随机拆相邻去噪行当独立测试。固定匹配初态与随机种子，同时保留原始 target-only baseline、上一版和候选。首先比较成功率及配对差异的置信区间，再比较双方成功任务的环境步数比值、中位数与尾部；同时单列失败/超时，并可采用失败记任务上限的全样本步数指标，避免“更早失败”被算成轨迹变短。

可讨论的起始非劣门槛：成功率最多下降 2 个百分点，成功任务配对步数比的中位数不超过 1.05、P90 不超过 1.10；这些是**尚未确认的研究容忍度示例**，不是现有验收结论。若用户要求无明显下降，样本量应由预定容忍度和统计功效决定。当前同一 task 的 2/2 成功只能作开发 pilot。

[OneDP，ICML 2025](https://proceedings.mlr.press/v267/wang25ba.html)通过沿 diffusion chain 的分布蒸馏压缩策略，并在机器人任务中评估。可借鉴“教师策略对齐 + 闭环验证”；其单步策略训练不等于我们的两步方向 draft，也不能直接证明环境步数保持。

## 3. L2 接受条件与阈值

当前代码实际使用的是未按维数取均值的 L2 范数：

`e_i = abs(sigma_(i+1) − sigma_i) × ||d_draft(x_i) − d_target(x_i)||_2`，接受条件 `e_i ≤ tau`。

这是同一输入处，一步 Euler 更新的有效动作状态误差度量；BF16 舍入和投影还需按实际执行核对。它不是原始 direction 的无权 L2，不是 MSE，也不是完整 target 轨迹的终点误差。见[误差实现](../../../投机采样/scripts/p0_batched_verify.py)。

现用 `tau = 0.007839680526450805` 可精确追溯到 2026-09-29 存档：**task8 的 beam1 第一、第二条边 successor-L2 合并后的 q90**，并在 task9 上做局部接受统计。这一校准没有运行新 policy action，因此 q90 只描述历史误差分布，不能解释为“90% 任务安全”“90% 成功率”或当前双候选的 90% 接受。见[来源实现](../../../review/OMISSIONS.md)、[原始存档](../../../投机采样/results/analysis/p0-libero-long-phaseb-k2-b2-verifier-replay-20260929/phase_b_result.json)。

建议先保持该值作模型比较参照，建立独立 calibration 集，用少量预先声明的阈值候选画接受率与局部/完整动作偏差曲线，例如 `0、0.25、0.5、1.0、1.5 × 当前阈值`；这是筛选网格示例，不是默认放宽。筛出少数候选后进行完整任务质量校准，取满足成功率与轨迹约束的阈值，冻结后用于未见测试。模型定稿后需要重新检查阈值；无法从当前数据诚实地给出“正确数值”。

旧树上的阈值扫描只能评价旧访问状态的反事实接受，阈值改变会改变后续状态，必须真实回放或重新闭环确认。可进一步评估分 sigma 门槛、归一化 L2 和动作通道最大误差，尤其避免总误差掩盖夹爪状态附近的关键偏差；每增加一项都需要独立质量证据，不能不断添加门槛来拟合这两个开发 episode。

[Accelerated Diffusion Models via Speculative Sampling，ICML 2025](https://proceedings.mlr.press/v267/de-bortoli25a.html)以随机高斯转移和 reflection-maximal coupling 实现精确版本，讨论中明确指出不能直接应用于确定性采样器；其放宽接受的温度变体也不再严格保留目标分布。见[作者原文 §3、§7–8](https://arxiv.org/html/2501.05370v2)。我们的确定性 direction + 非零 L2 阈值是近似接受，不能引用该论文宣称严格无损；为套用公式而加入噪声还会改变当前 baseline。

## 4. “每次输出两个”的两种含义

| 含义 | 当前状态 | 建议 |
|---|---|---|
| 同一个降噪步输出两个方向候选，即分支宽度 B=2 | 当前已经联合训练、一次输出 | 保留接口，先改训练；检查双头覆盖和强制间距的实际贡献 |
| 一次输出连续两个未来降噪步，即深度 K=2 的整段预测 | 当前通过递归生成，不是单次整段输出 | 后续单列消融，需要第二步与第一步预测状态相容 |

当前 root 一次 draft 得到两个 parent，随后每个 parent 各调用一次 draft 得到四个 leaves，所以是**两层依赖、实际三次小模型前向**。第二层两个 parent 可以设计 batch 合并，先做这一实现改进，比直接改变整段预测语义更容易核查；还要验证数值和收益。见[树构建](../../../投机采样/scripts/p0_batched_verify.py)。

一口气预测两个未来方向是可行研究方向，但第二个方向必须适合 `x_1 = step(x_0, predicted_d_0)`，不能仅学习纯教师 `x_1` 上的标签。若同时保留 B=2、K=2 的四条路径，输出规模与条件依赖也不只是两个向量。可以先做条件化的第二头或两步展开训练，再决定是否整段并行。

[Medusa，ICML 2024](https://proceedings.mlr.press/v235/cai24b.html)用多头并行预测未来 token，再进行树验证；这对应“多个未来位置”，而不是我们当前同一步的两个候选。借鉴多头思想合理，但连续状态递归依赖与质量机制必须另外验证。

## 5. 接受后选路的精确定义

用户已认可“先阈值筛选，再选总误差最小”。建议固定为：

1. 逐边检查误差，首边失败则整条后继分支不可提交；次边失败时保留通过的首边。
2. 从合法前缀中优先选最长者，避免总误差较小的一步路径抢过可接受的两步路径。
3. 长度相同时，仅比较**保留前缀**的误差总和；再以固定节点次序打破平局。
4. 无合法 draft 前缀时提交 root target；长度 1 时提交该 parent 的 target 更新；长度 2 时消费已算出的 leaf target bonus。

当前 `depth_then_cost` 已实现最长可接受前缀优先；有合法两步路径时也已符合上述选法。但同为长度 1 时，它仍以 `first_cost + rejected_second_cost` 排序，保留了旧 global 的 tie-break，尚未变成只比较首边误差。新定义应作为**独立版本**实施和测试，不改写封存 v2，也不把“语义更直接”先宣称为任务质量改善。见[现用 selector](../../../投机采样/experiments/bonus_acceptance_v2/selection.py)。

每条边达标不等于整段终点有严格误差界；两条局部误差相加也只是排序代理。接受条件要在 target 验证后才知道，因此这里的剪枝作用于提交选择，不能节省已经完成的七节点验证前向。

## 按顺序执行的下一步

1. **协议与 CPU：** 将合法前缀选路写成独立候选，检查长度 0/1/2、失败父节点、拒绝子节点、边界相等、固定 tie-break、bonus/fallback 状态；锁定数据划分、质量指标和阈值参照。
2. **数据与训练：** 审计可复用标签，在当前 bonus 真实访问状态上补教师标签；先保留 MLP，只比较新数据/步长对齐损失/双头间距消融。模型保持原值参照，避免以放宽阈值冒充学习改进。
3. **结构：** 对最有效的训练方式做一层 Transformer 与容量参照 MLP 对照；额外 target 条件特征单列。保留两候选和两层递归，整段预测不与结构试验捆绑。
4. **阈值与闭环：** 少量入围模型做独立阈值校准，冻结候选，再比较原 T、上一版与新候选的成功率、成功任务步数及失败/超时；不靠两条开发轨迹完成正式非劣结论。
5. **最后速度：** 质量达标后，再按既定完整 diffusion/chunk 与 LIBERO episode 协议测试；保持原 baseline 和上一版双重对照。

本轮 GPU 消耗为 0；沿用最近封账累计 14,118.698 秒（3.922 小时），用户 5 小时上限剩余约 64.7 分钟。该余量不能预先承诺足够完成上述全部训练和有统计功效的多任务验证；后续每个实际执行方案需依据剩余资源拆分，不能把有限 pilot 写成正式成功率保证。
