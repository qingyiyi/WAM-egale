# Bonus：原 Torch 精度、完整 chunk 与六条完整任务结果

2026-10-13T19:23:30+08:00（Asia/Shanghai）。正式计时完成后独立 CPU 审核，HW 走原生 chat 追加，不修改完成的 Cycle/state。

**结论：在两个真实长 KV 固定状态上，bonus 是明确的推理优化；完整任务相对当前关闭版的稳定收益仍未证明。** 长 KV 完整 chunk 相对原始 T 快约 1.48×，相对 OFF 快 1.16–1.17×。两任务完整 E2E 合计相对原 T 为 1.2101×（耗时少17.36%），相对 OFF 仅1.0180×（少1.76%）；初态3反而慢约3.57%。三个配置均2/2成功。本轮是一个 LIBERO Long/task0、两个初态的 pilot。

T=原始 target-only；OFF=direction K2/B2 + shared KV + O1/O2/O3；BONUS=OFF 开启原来已有的 bonus。三方都在本轮重新计时；历史耗时不作主分母。没有第三层 draft 或 Megatransformer 实现。

## 1. 验证为什么可以推进第三步

一次 target 验证前向输出的是 denoising direction，scheduler 才提交状态。根输入 x0 的 target direction 验证第一层 draft，第二层输入 x1 的 direction 验证下一层 draft，所选叶输入 x2 的 target direction 可再更新得到 x3。叶 direction 已在同一批验证中算好；旧 OFF 没提交这一步，BONUS 才利用它。

| 分支 | OFF 实际提交 | BONUS 实际提交 |
|---|---:|---:|
| 第一层拒绝 | 1次 target 更新 | 1次 target 更新 |
| 第一层接受、第二层拒绝 | 1 draft + 1 target = 2 | 1 draft + 1 target = 2 |
| 两层均接受 | 2次 draft 更新 | 2次 draft + 1次叶 target = 3 |

剩余不足三步时，BONUS 回到原 target 尾段，完整50次去噪更新全部完成。两次 draft 指选中路径的两个深度；当前 B2 展开整棵树时，root 调一次 MLP、两个中间父节点各调一次，实际每树3次 MLP 前向。验证逻辑节点仍7个、CFG仍14行。

本轮平均每棵验证树的实际推进 OFF **1.745614**→BONUS **2.469553**。验证树1026→739，draft 前向3078→2217，动作 target 调用1122→852（含普通/尾段和terminal；不是FLOPs或墙钟）。BONUS共提交514个额外 target 更新。因多一个完整chunk，总提交更新1850→1900，未靠减少50步采样获取速度。

## 4. 为什么固定 chunk 快，新增 E2E 收益却小

相对OFF，两任务policy省 **14.510秒（5.12%）**，KV/观察省2.874秒、客户端余项省0.130秒；reset增加 **7.089秒**，净省 **10.426秒（1.76%）**。BONUS reset约占新总耗时43.55%。reset共同代码未修改，不能把这7.089秒直接归为bonus新增计算；CPU T5/线程/进程调度的批次波动仍是候选解释，未独立profile分摊。

初态3实际policy增加11.387秒，其中chunk数由18到19；平均policy/chunk OFF7.5265秒、BONUS7.7297秒，约慢2.70%。初态4的policy下降25.897秒。合计平均policy/chunk少约7.62%，低于固定长KV状态的13.53–14.38%耗时下降。

固定状态计时是单模型、相同输入、长KV稳态；真实轨迹包含首块及短中长上下文，并且BONUS改变动作/输入状态。本轮完整任务还有同卡双模型收集负载，三轮伙伴配置不完全相同。上述账本精确定位了增减阶段，但不能唯一判定初态3每chunk增时的kernel原因，也不能用两个固定状态的比例直接乘整个episode。后续需要真实短/中KV和代表性轨迹状态回放，而不是先增树深度或只盯NFE。

## 5. 精度、存档及资源

CPU六组同共享注意力后端完整BF16/50步/30层helper对照通过；原始未共享CPU参考仍有46元素差异、最大绝对差0.015625，分支计数一致，失败记录保留。真实GPU原Torch bonus对照在两个长KV状态逐位通过，未降低门槛。CPU替代注意力差异不能冒充生产GPU精度失败或全平台逐位通过。

独立CPU读取两个原Torch/优化bonus输出与轻量终态对照；完整KV逐位检查在GPU worker进行。T与OFF整局对历史数值oracle的**221对存档张量**、命令及初/终环境状态逐字节回归通过；历史仅作数值oracle。BONUS改变轨迹，不强求与OFF动作一致；整局未归档每chunk全部KV，不宣称全轨迹KV独立逐位证明。

新增8977次target前向、GPU1650.623秒（27.51分钟），累计42216/50000次、13143.636/18000秒（约3小时39分）。7次模型启动、6次EGL初始化、一次有限GPU尝试，无GPU重试。GPU采集闭合，所有本实验进程退出，分配显存/compute/graphics清理记录为空。首次CPU启动预检因磁盘保留量等于floor+output被拒绝，0GPU；旧失败计划/日志和原两份源码版本另存，新独立计划提高准入余量后10项预检通过。
